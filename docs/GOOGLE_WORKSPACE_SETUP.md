# 구글 드라이브 연결 안내

Firebase 대신 학교 공유드라이브의 Google Sheets와 Apps Script를 사용합니다. 새 유료 서비스나 결제를 연결하지 않습니다. 학교 저장 용량과 Apps Script 사용 한도는 적용됩니다.

## 현재 상태
- 학교 설정, 20개 부서, 교표와 데이터 저장 코드 구현.
- 모의 서버 검사와 앱 빌드 통과. 실제 학교 로그인과 시트 저장은 미검증.
- Apps Script 접속이 자동 승인 검토에 차단되어 실제 DB 생성과 배포는 대기 중.

## 준비
```text
npm ci
npm test
npm run build:gas
npm run build
```
배포 파일은 apps-script 폴더의 Code.gs, Config.gs, Index.html, Privacy.html, appsscript.json입니다. 생성 HTML과 Config.gs는 Git에서 제외합니다. firestore.rules는 이전 방식의 참고 파일이며 배포하지 않습니다.

npm run preview:gas는 http://127.0.0.1:4319 에서 관리자 역할을 흉내 내는 로컬 검사입니다. 메모리에만 저장하므로 운영에 사용하지 마세요.

## 실제 연결 순서
1. smt_kor03@seongmohs.djsch.kr 학교 계정으로 작업합니다.
2. 지정 공유드라이브 폴더 아래에 데이터용 구글 시트를 준비합니다. 일반 교직원이 시트를 직접 편집하면 앱 권한을 우회하므로 관리자 전용 제한된 접근 폴더가 필요합니다. 기존 권한을 임의로 변경하지 않습니다. 공유드라이브 관리자는 신뢰하는 관리자입니다.
3. 학교 계정 Apps Script 프로젝트에 배포 파일을 넣고 제공된 매니페스트와 Drive 고급 서비스 v3를 적용합니다.
4. 스크립트 속성에 SPREADSHEET_ID, SHARED_DRIVE_ID, SHARED_FOLDER_ID를 지정합니다. 실제 값은 공개 코드에 넣지 않습니다.
5. 관리자 계정으로 setupDatabase를 실행합니다. 기존 내용을 지우지 않고 records 시트를 준비합니다. 공개 공유 및 일반 사용자의 편집 권한이 있으면 중단합니다.
6. 웹 앱 배포: 실행 사용자=배포자, 접근=학교 조직 내부. 조직 내부 옵션이 없거나 관리 정책이 막으면 중단합니다. 누구나 접근으로 바꾸지 않습니다.
7. 발급된 /exec 주소를 학교 계정으로 엽니다. 계정 이메일을 확인할 수 없으면 서버가 거부합니다.

## 배포 후 검사
- 로그아웃 및 외부 계정 접근 거부.
- 관리자와 별도 교사 계정으로 부서 범위 밖 편집 차단.
- 임시 업무 저장, 새 브라우저 재조회, 수정과 검사 기록 삭제.
- 본인 제출 확인, 교직원 명단, 게시글, 서식, PDF 일정 가져오기.
- 모바일 화면, 브라우저 오류, 실제 URL에 도름스체크. 로그인으로 검사할 수 없는 항목은 미확인으로 기록.

## 운영 차이
- 저장 직후 다시 읽고 다른 사용자 변경은 약 60초마다 갱신합니다.
- 저장 잠금과 중복 요청 방지를 적용합니다. 업무와 과제 수정 중 원본 변경 시 다시 열어야 합니다.
- 최대 5,000개 기록이며 전체 시트를 읽고 쓰므로 실제 학교에서 속도를 확인해야 합니다.
- 같은 학교 도메인의 학생 계정도 조회할 수 있습니다. 학생 계정이 같은 도메인이라면 운영 전 교직원 허용 목록을 추가해야 합니다.
- Apps Script에서는 일반 PWA 설치와 차이가 있으므로 브라우저 즐겨찾기를 사용할 수 있습니다.
- 삭제는 앱 기록을 지우며 Google 버전 기록과 기관 보존 정책까지 제거하지 않습니다.
- 업데이트 전 데이터 시트를 백업하고 새 배포 버전을 만듭니다. 되돌릴 이전 버전 번호를 기록합니다.
